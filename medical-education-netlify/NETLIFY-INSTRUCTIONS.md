# როგორ გადავიტანოთ საიტი Netlify-ზე

ეს არის მხოლოდ Netlify-ისთვის გამზადებული პროექტი. ყველა კოდი პაკეტშია; არსებულ კოდში ნაწილების ხელით ჩასმა არ გჭირდება. თავდაპირველად პროექტი ჯერ არ არის გამოქვეყნებული შენს Netlify ანგარიშზე.

## 1. რას მიიღებ

საიტი გაიხსნება Netlify-ის მისამართზე. პირველი გვერდი იქნება ელფოსტისა და პაროლის შესაყვანი ფორმა. მხოლოდ შენს მიერ მითითებული ადმინისტრატორი შევა. საჯარო რეგისტრაცია არ არსებობს.

„ადმინისტრირება“ განყოფილებაში დაამატებ ორგანიზაციის ბმულს, მის სახელსა და სპეციალობას. ბმული შეინახება ბაზაში და პირველივე შემოწმება დაიწყება. წყაროს შემდეგ შეცვლი, გამორთავ ან ხელახლა ჩართავ. ისტორია და წაკითხვის შეცდომები ჩანს პანელში.

Netlify ავტომატურად დაიწყებს ჩართული წყაროების შემოწმებას ყოველ დღე თბილისის 08:00-სა და 18:00-ზე. დღის განრიგი ინტერნეტსერვერზე მუშაობს — გვერდი ან შენი კომპიუტერი გახსნილი არ უნდა იყოს. ChatGPT-ის გამოწერა ამ განახლების პროცესში არ მონაწილეობს. ჰოსტინგის ანგარიშს უნდა ჰქონდეს მოქმედი რესურსი და ფუნქციებზე წვდომა.

განრიგი მოკლე Scheduled Function-ს იყენებს, თვითონ კითხვა კი Background Function-ში ხდება: Netlify-ის დაგეგმილ ფუნქციას 30 წამი აქვს, ფონურს — მაქსიმუმ 15 წუთი. კოდი ერთდროულად ორ წყაროს კითხულობს და ძველად შემოწმებულ ბმულებს პირველ რიგში ამუშავებს. თუ რეესტრი იმდენად გაიზრდება, რომ ერთი გაშვება ვერ დაეტევა, დაუმთავრებელი წყაროები შემდეგ განახლებაზე პრიორიტეტულად მოწმდება.

არსებული რეესტრი 31 წყაროთი იწყება. ეს არ ნიშნავს საქართველოში ყველა ორგანიზაციის სრულ დაფარვას. ახალი ორგანიზაციების ზოგადი ინტერნეტძიება დამოუკიდებელ ვერსიაში ჩართული არ არის; ახალი ბმული ადმინისტრირების პანელიდან დაამატე. მიუწვდომელ გვერდზე ან პოსტერის სურათში დარჩენილი ინფორმაცია შეიძლება ვერ წაიკითხოს.

## 2. ZIP-ის გახსნა

გადმოწერე ZIP და გახსენი კომპიუტერში. შიგნით იქნება საქაღალდე `medical-education-netlify`. მასში უნდა ჩანდეს `package.json`, `netlify.toml`, `app`, `lib`, `db` და `netlify`.

ზუსტად ეს საქაღალდეა პროექტის ძირი. მისი შიგთავსი უნდა ატვირთო GitHub-ზე, რათა Netlify-მ ააწყოს სერვერიანი საიტი. ZIP-ის ან საქაღალდის პირდაპირ Netlify Drop-ში ჩაგდება ამ პროექტს ვერ ააწყობს.

## 3. პაროლისა და საიდუმლო გასაღებების შექმნა

კომპიუტერში დააყენე Node.js 22.13 ან ახალი ვერსია [ოფიციალური გვერდიდან](https://nodejs.org/). შემდეგ პროექტის საქაღალდეში გახსენი Terminal და გაუშვი:

```sh
npm ci
npm run admin:setup
```

მიუთითე შენი ელფოსტა და მინიმუმ 12 სიმბოლოს პაროლი. პროგრამა შენს კომპიუტერში შექმნის `.env.local` ფაილს. პაროლი ამ ფაილში პირდაპირ არ ინახება — მხოლოდ მისი ჰეში. შეინახე პაროლი შენს პაროლების მენეჯერში.

`.env.local` შეიცავს შემდეგ გარემოს პარამეტრებს:

- `ADMIN_EMAIL` — ადმინისტრატორის ელფოსტა.
- `ADMIN_PASSWORD_HASH` — პროგრამის მიერ გამოთვლილი პაროლის ჰეში; ჩვეულებრივი პაროლი აქ არ ჩაწერო.
- `SESSION_SECRET` — შესვლის სესიის ხელმოწერის გასაღები.
- `CRON_SECRET` — ფონური განახლების გამშვების გასაღები.
- `OWNER_USER_ID` — დატოვე ფაილში არსებული მნიშვნელობა; იგი ძველი ჩანაწერების მფლობელს შეესაბამება.
- `APP_URL` — მოგვიანებით ჩაწერ შენი საიტის ნამდვილ მისამართს, მაგალითად `https://academia-example.netlify.app`.
- `TRACKER_SCHEDULE_ENABLED` — დატოვე `true`, როცა ავტომატური განახლება გინდა. `false` აჩერებს ავტომატურ გაშვებას.

მნიშვნელობები მხოლოდ შენს კომპიუტერში და Netlify-ის გარემოს პარამეტრებში გადაიტანე. `.env.local` GitHub-ზე არ ატვირთო. ZIP მხოლოდ `.env.example`-ს შეიცავს — რეალური საიდუმლო გასაღებები მასში არ არის. არცერთ გასაღებს არ დაუმატო `NEXT_PUBLIC_` წინსართი.

## 4. პროექტის ატვირთვა GitHub-ზე

შედი [GitHub](https://github.com/)-ზე და შექმენი ახალი **Private** საცავი. სახელი შეგიძლია იყოს `medical-education-netlify`. ცარიელი საცავი შექმენი, დამატებითი საწყისი README-ის გარეშე.

ფაილების ბრაუზერით ატვირთვისას აირჩიე `uploading an existing file` ან `Add file → Upload files`. ატვირთე `medical-education-netlify` საქაღალდის შიგთავსი. მთავარ გვერდზე პირდაპირ უნდა ჩანდეს `package.json` და `netlify.toml`; ისინი სხვა საქაღალდეში არ უნდა იყოს ჩადებული.

არ ატვირთო `node_modules`, `.next`, `.env.local`, სარეზერვო ასლები, ატვირთული სამედიცინო დოკუმენტები ან პაროლები. ბრაუზერით ატვირთვისას ამ გამორიცხვებს თავად მიაქციე ყურადღება — `.gitignore` ბრაუზერის ატვირთვას ავტომატურად არ მართავს.

Terminal-ით ატვირთვის ალტერნატივა, თუ Git უკვე გაქვს:

```sh
git init
git add .
git commit -m "Add medical education Netlify app"
git branch -M main
git remote add origin https://github.com/YOUR-ACCOUNT/medical-education-netlify.git
git push -u origin main
```

`YOUR-ACCOUNT` შეცვალე შენი GitHub ანგარიშით. ამ გზაზე `.gitignore` ავტომატურად გამორიცხავს პარამეტრებისა და სამუშაო ფაილებს.

## 5. Netlify-ში დაკავშირება

შედი [Netlify](https://app.netlify.com/)-ზე. შექმენი ახალი პროექტი არსებული საცავიდან: `Add new project → Import an existing project → GitHub`. თუ ღილაკების სახელები შეიცვალა, მოძებნე GitHub საცავის დაკავშირების მოქმედება.

დაუშვი წვდომა მხოლოდ საჭირო საცავზე და აირჩიე `medical-education-netlify`.

აწყობის პარამეტრები:

- წარმოების ტოტი — `main`.
- პროექტის საწყისი საქაღალდე — ცარიელი, თუ `package.json` საცავის ძირშია.
- აწყობის ბრძანება — `npm run build`.
- გამოსაქვეყნებელი საქაღალდე — `.next`.
- ფუნქციების საქაღალდე — `netlify/functions`.
- Node.js — `22`.

ეს პარამეტრები `netlify.toml`-შიც წერია. Next.js-ის მხარდაჭერას Netlify ავტომატურად ამზადებს. ძველი HTML-ისთვის შექმნილი `/* /index.html 200` გადამისამართება ამ პროექტს არ დაუმატო.

გაუშვი პირველი განთავსება. პირველი აწყობა მონაცემთა ბაზას არ მოითხოვს; ბაზისა და გასაღებების გამართვამდე შესვლა არ იმუშავებს.

## 6. მონაცემთა ბაზის ჩართვა

Netlify-ის პროექტში გახსენი `Data & Storage → Database` და შექმენი მონაცემთა ბაზა. გამოიყენე Netlify Database. ცალკე Cloudflare ანგარიში, D1 ან R2 არ გჭირდება.

ბაზის დაკავშირების შემდეგ Netlify ავტომატურად გადასცემს სერვერს `NETLIFY_DB_URL` პარამეტრს. იგი ბრაუზერში არ გამოდის. კოდი იყენებს Netlify-ის `getConnectionString()` მეთოდსა და PostgreSQL მონაცემთა ბაზას.

ხელახლა გაუშვი განთავსება. საქაღალდეში `netlify/database/migrations/0001_initial/migration.sql` უკვე არის ბაზის შესაქმნელი კოდი. Netlify Database მას გამოქვეყნებამდე ავტომატურად გაუშვებს. თუ ამ ეტაპზე შეცდომა გამოჩნდა, `Deploy log`-ში ნახე Database/Migrations ჩანაწერი — სამუშაო საიტის გამართულად გამოცხადებამდე მიგრაცია წარმატებული უნდა იყოს.

ბაზაში ავტომატურად შეიქმნება უნივერსიტეტების/ექიმების/სხვა სამუშაო ჩანაწერების, ტრეკერის, შესვლის მცდელობებისა და ფონური განახლების ბლოკირების სტრუქტურები.

## 7. გარემოს პარამეტრების შევსება

Netlify-ში გახსენი პროექტის პარამეტრები და `Environment variables`. გადაიტანე `.env.local`-ის შესაბამისი მნიშვნელობები. გასაღებები საიდუმლო პარამეტრებად შეინახე. ისინი უნდა იყოს ხელმისაწვდომი როგორც სერვერის ფუნქციებისთვის, ასევე აწყობისას.

`APP_URL` აუცილებლად შეცვალე ახალი საიტის ნამდვილი `https://...netlify.app` მისამართით. პირადი დომენის დამატებისას განაახლე იგი იმავე დომენზე. არ ჩაწერო ChatGPT-ის ძველი საიტის მისამართი.

წარმოების გარემოში ჩაწერე `TRACKER_SCHEDULE_ENABLED=true`. თუ Preview გარემოსთვისაც ავსებ პარამეტრებს, იქ `false` გამოიყენე, რათა სატესტო განთავსებამ დამოუკიდებლად არ განაახლოს ბაზა. ფონურ ფუნქციასაც აქვს წარმოების გარემოს შემოწმება.

პარამეტრების ცვლილების შემდეგ ხელახლა განათავსე პროექტი. შემდეგ ახალ საიტზე შეიყვანე შენი ელფოსტა და ადრე არჩეული პაროლი.

თუ მუქი ფორმა ჩანს და ავტორიზაციაში 503 გიწერს, გადაამოწმე: შეიქმნა თუ არა Database, შესრულდა თუ არა მიგრაცია და შეავსე თუ არა ყველა გასაღები. თუ 401 ჩანს, ელფოსტა ან პაროლი არ ემთხვევა. ათზე მეტი შესვლის მცდელობის შემდეგ იგივე მისამართზე 15 წუთიანი შეზღუდვა მოქმედებს.

## 8. ავტომატური შემოწმების დადასტურება

Netlify-ის `Functions` განყოფილებაში უნდა ჩანდეს:

- `tracker-schedule` — განრიგით გამშვები.
- `tracker-background` — წყაროების ფონური წამკითხველი.

`tracker-schedule`-ს უნდა ჰქონდეს Scheduled ნიშნული და შემდეგი გაშვების დრო. Netlify-ის განრიგია `0 4,14 * * *` — UTC დროით 04:00 და 14:00, ანუ თბილისის 08:00 და 18:00.

პირველი შემოწმებისთვის ადმინისტრატორის პანელში დააჭირე „ყველა წყაროს განახლება“. იგი სერვერის ფონურ პროცესს გაუშვებს. რამდენიმე წუთში გადახედე შემოწმების ისტორიას. გვერდი შედეგებს ყოველ წუთში ხელახლა ტვირთავს.

კონკრეტული წყაროს ხელით შემოწმება პირდაპირ მოთხოვნად მუშაობს და შეიძლება Netlify-ის მოკლე მოთხოვნის ლიმიტს მიუახლოვდეს. ფონური შემოწმება მთელი რეესტრისთვის გამიზნულია. წაკითხვის შეცდომა წარმატებულ შემოწმებად არ ჩაითვლება.

Netlify-ის ფუნქციებისა და ბაზის რესურსი შეიძლება ფასიანი იყოს ან უფასო ანგარიშის კვოტით შეიზღუდოს. ეს დამოკიდებულია ანგარიშის პირობებსა და მოხმარებაზე. მუდმივ უფასო მუშაობას პაკეტი არ გპირდება; მოქმედი ჰოსტინგის პირობებში იგი ChatGPT-ისგან დამოუკიდებელია.

## 9. ძველი მონაცემების გადატანა

არსებულ ChatGPT საიტზე „ადმინისტრირება“-დან ჩამოტვირთე `medical-education-backup.json`. ZIP სამუშაო მონაცემებს არ შეიცავს; იგი მხოლოდ პროგრამის კოდია.

ახალი Netlify ბაზის დაკავშირების დეტალებიდან აიღე წარმოების PostgreSQL connection string. მხოლოდ შენს კომპიუტერში დაამატე `.env.local`-ში:

```text
DATABASE_URL=აქ_ჩაწერე_ბაზის_ნამდვილი_მისამართი
```

ეს მისამართი პაროლს შეიცავს — არ გააზიარო და GitHub-ზე არ ატვირთო. სანამ ძველი მონაცემები გადმოგაქვს, Netlify-ში დროებით მიუთითე `TRACKER_SCHEDULE_ENABLED=false` და ხელახლა განათავსე. ახალ საიტზე ხელით განახლებაც არ გაუშვა: აღდგენის სკრიპტი მოითხოვს ცარიელ სამუშაო ბაზას.

პროექტის საქაღალდეში გაუშვი:

```sh
npm run db:setup
npm run backup:restore -- medical-education-backup.json
```

აღდგენა მხოლოდ ცარიელ ბაზაში მუშაობს და მთლიანად ტრანზაქციულია: შეცდომისას ცვლილებები უქმდება. უკვე არსებული სამუშაო მონაცემების თავზე არაფერს გადაწერს. `OWNER_USER_ID` უნდა ემთხვეოდეს ასლის მფლობელს.

საიტზე გადაამოწმე უნივერსიტეტები, ექიმები, განრიგები და სხვა ჩანაწერები. შემდეგ ხელახლა ჩართე `TRACKER_SCHEDULE_ENABLED=true` და განათავსე პროექტი.

## 10. ატვირთული ფაილების გადატანა

JSON ასლი შეიცავს ჩანაწერებსა და ფაილების გასაღებებს, მაგრამ თვითონ ფაილების შიგთავსი ცალკე უნდა გადაიტანო. ახალი ატვირთვები პირდაპირ Netlify Blobs-ში ინახება და საჯარო ბმულით არ გაიცემა.

ძველი ფაილებისთვის:

1. ძველ საიტზე ჩამოტვირთე ფაილები.
2. პროექტში შექმენი `migration-files` საქაღალდე და იქ მოათავსე ჩამოტვირთული ასლები.
3. დააკოპირე `files-manifest.example.json` ფაილად `files-manifest.json`. თითოეულ ფაილზე მიუთითე ძველი სრული `key` და ახალი ადგილობრივი `localPath`. ძველი გასაღები ასლში შესაბამისი უნივერსიტეტის/ექიმის/სერტიფიკატის ჩანაწერში ჩანს; მისი სრული მნიშვნელობა უცვლელად დატოვე.
4. შენს კომპიუტერში `.env.local`-ში დაამატე `NETLIFY_SITE_ID` და `NETLIFY_AUTH_TOKEN`, რომლებიც შენი პროექტისა და ანგარიშის პარამეტრებიდან მიიღება. ეს გასაღებები მხოლოდ ადგილობრივი გადატანის სკრიპტისთვისაა; საიტის გარემოში მათი ჩაწერა არ გჭირდება.
5. გაუშვი:

```sh
node scripts/import-files.mjs files-manifest.json
```

სკრიპტი უკვე არსებულ ფაილს არ გადაწერს. ძველი გასაღების შენარჩუნება აუცილებელია, რათა ჩანაწერიდან ფაილის ბმული კვლავ მუშაობდეს. ფაილების გახსნის დადასტურების გარეშე გადატანა სრულად დასრულებულად არ ითვლება. ახალი ატვირთვების ლიმიტია 3 მბ; დიდ ძველ ფაილებს Netlify-ის პასუხის მოცულობის შეზღუდვა შეიძლება შეეხოს.

## 11. დახურული სისტემის შემოწმება

გამოდი ანგარიშიდან და ახალი ფანჯრიდან სცადე სამუშაო გვერდის გახსნა — შესვლის ფორმაზე უნდა გადაგიყვანოს. მონაცემებისა და ფაილების მისამართებმა შესვლის გარეშე 401 უნდა დააბრუნოს. სხვა ელფოსტით შესვლა არ უნდა მოხდეს. გასვლის ღილაკმა სესია უნდა გააუქმოს.

ერთი ოფიციალური ბმული დაამატე „ადმინისტრირება“-ში. დაადასტურე, რომ შენახვის შემდეგ ჩანს, ხელახლა შესვლის შემდეგაც რჩება და ახალი დაგეგმილი შემოწმებისას ისტორიაში ჩანაწერი ემატება.

სესია მოქმედებს 8 საათით. პაროლის დავიწყებისას ახალი ჰეში შენს კომპიუტერში შექმენი და Netlify-ში შეცვალე `ADMIN_PASSWORD_HASH`; ასევე შეცვალე `SESSION_SECRET`, რათა ძველი შესვლის სესიები გაუქმდეს. პარამეტრების ყოველი ცვლილების შემდეგ ხელახლა განათავსე პროექტი.

ძველი ChatGPT-ის ავტომატური დავალება გამორთე მხოლოდ ახალი Netlify საიტის პირველი წარმატებული დაგეგმილი შემოწმებისა და ძველი მონაცემების/ფაილების გადამოწმების შემდეგ.

## 12. რომელი ფაილი რას აკეთებს

`app/workspace.tsx` არის მთავარი სამუშაო სივრცე. `app/tracker.tsx` შეიცავს უსგ ტრეკერსა და ადმინისტრირებას. `app/login/page.tsx` არის შესვლის ფორმა. `proxy.ts` იცავს გვერდებსა და მოთხოვნებს. `lib/session.mjs` ამოწმებს პაროლსა და სესიას. `db/index.ts` და `db/schema.ts` მონაცემთა ბაზის კოდია.

`netlify/functions/tracker-schedule.ts` იწყებს ავტომატურ დავალებას. `netlify/functions/tracker-background.ts` ფონურ პროცესს უშვებს. `lib/tracker-job.ts` მართავს მთლიანი რეესტრის შემოწმებას, გაშვებების გადაფარვასა და დროის ბიუჯეტს. `lib/tracker-collector.ts`, `lib/tracker-parser.ts` და `lib/tracker-workbook.ts` საჯარო გვერდებსა და ოფიციალურ კატალოგებს კითხულობს.

`netlify.toml` განსაზღვრავს ჰოსტინგის აწყობასა და განრიგს. `package-lock.json` აფიქსირებს შემოწმებულ დამოკიდებულებებს. ამიტომ დამონტაჟებისთვის გამოიყენე `npm ci`.
